0. PURPOSE

ISPAD defines how finalized reality is acted upon.

It answers one question only:
How do organizers and partners operate once reality has occurred (or is sealed)?

ISPAD is not discovery.
ISPAD is not marketplace.
ISPAD is not governance.

ISPAD is command and consequence.

⸻

1. NON-NEGOTIABLE INVARIANTS
	1.	ISPAD operates only after KAPIA.
	2.	ISPAD never creates or modifies truth.
	3.	ISPAD never consumes or issues value.
	4.	ISPAD never writes to SPIRAL.
	5.	ISPAD only references finalized artifacts.
	6.	ISPAD has no independent authority.

⸻

2. CANONICAL PLACEMENT

ISPAD exists in system state 1 (consequence):

UPAD (0) → KAPIA (⊙) → ISPAD (1)

ISPAD completes the system loop.

⸻

3. CORE DEFINITIONS

Consequence:
Actions taken in reference to finalized reality.

Operational Actor:
Any non-consumer entity acting post-reality (organizer, venue, finance, ops).

Reference View:
A read-only projection of truth (PoP, EVENT closure, SPIRAL turns).

⸻

4. WHAT ISPAD DOES

After KAPIA, ISPAD MAY:

• coordinate operations
• present finalized attendance
• expose canonical analytics
• enable reporting and compliance
• trigger settlement eligibility
• apply Third Space decisions
• manage post-event workflows

All actions are referential, not generative.
