0. Purpose

IAM.MAI governs whether a transition is allowed to occur.

It answers one question only:

Is this transition legitimate now?

IAM.MAI does not:
	•	reason about content
	•	infer intent
	•	decide truth
	•	classify patterns
	•	execute actions
	•	manage value
	•	model identity

IAM.MAI is a gate, not a brain.

⸻

1. Canonical Statement (LOCKED)

IAM.MAI = Transition Legitimacy Protocol
Transition Set: { ⊙ HOLD, FINALIZE, INVALIDATE, EVOLVE }

All references to IAM.MAI MUST reduce to this statement.

No alternate meanings are valid.

⸻

2. Transition Set (Closed)

IAM.MAI supports exactly four transitions.

2.1 ⊙ HOLD
	•	Default state
	•	No irreversible change permitted
	•	Accumulation and observation allowed
	•	No sealing, no mutation

2.2 FINALIZE
	•	Irreversible commit
	•	State becomes fixed
	•	Entry is written to continuity memory
	•	No further modification permitted

2.3 INVALIDATE
	•	Irreversible rejection
	•	State is marked as not standing
	•	No downstream reliance allowed

2.4 EVOLVE
	•	Irreversible creation of a successor state
	•	Prior state remains referenceable
	•	Lineage link is mandatory

Hard Rule:
No other transitions exist.
No extensions permitted.

⸻

3. Lineage Requirement

Every irreversible transition (FINALIZE, INVALIDATE, EVOLVE) MUST:
	•	reference a parent state (except genesis)
	•	produce a unique state identifier
	•	be written to continuity memory (SPIRAL)

Silent transitions are forbidden.

	•	closed transition set
	•	explicit lineage
	•	irreversible commits
