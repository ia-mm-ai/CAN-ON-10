0. PURPOSE

KAPIA defines the single irreversible boundary where potential collapses into reality.

It answers one question only:
Is reality allowed to cross here now?

KAPIA does not create truth.
KAPIA does not decide legitimacy.
KAPIA does not manage value.

KAPIA is a threshold, not an action.

⸻

1. NON-NEGOTIABLE INVARIANTS
	1.	KAPIA is irreversible — once crossed, potential cannot return.
	2.	KAPIA exists only inside an EVENT.
	3.	KAPIA consumes value, not truth.
	4.	KAPIA does not authorize transitions — IAM.MAI does.
	5.	KAPIA cannot reopen after EVENT closure.

⸻

2. CANONICAL STATES

KAPIA has no lifecycle of its own.
It is conditionally active only when:

• EVENT state = ⊙ (Live)

Outside that state, KAPIA is inert.

⸻

3. CORE DEFINITIONS

Threshold:
A point of no return between potential and fact.

Crossing:
The moment when admissible presence collapses into reality.

Admissibility:
A condition where all required preconditions are satisfied.

⸻

4. CANONICAL PLACEMENT

KAPIA sits between system states:

0 → ⊙ → 1

• 0 — potential (UPAD)
• ⊙ — admissible reality (KAPIA active)
• 1 — consequence (ISPAD)

KAPIA is the ⊙.

⸻

5. ADMISSIBLE INPUTS

KAPIA MAY accept only:

• a valid EVENT context (state = ⊙)
• a valid entitlement (ticket / access right)
• sufficient Value Units (VU) to be consumed
• a human-operated gate action (attestation context)

KAPIA MUST reject:

• pre-event attempts
• post-closure attempts
• duplicate crossings
• simulated or inferred presence

⸻

6. THRESHOLD BEHAVIOR

6.1 HOLD (default)
• presence may be observed or queued
• no value is consumed
• no truth is created

6.2 CROSS (implicit)
When admissibility is satisfied:

• VU is consumed (irreversible)
• Balance ceases to apply for that entry
• presence becomes eligible for PoP instantiation

Important:
CROSS does not create PoP.

⸻

7. RELATIONSHIP TO PoP

• KAPIA enables PoP eligibility
• PoP instantiation requires:
	•	KAPIA crossing, and
	•	IAM.MAI authorization (FINALIZE)

KAPIA is necessary but not sufficient for PoP.

⸻

8. RELATIONSHIP TO IAM.MAI

IAM.MAI governs:

• whether PoP may be FINALIZED
• whether a crossing is INVALIDATED
• whether EVOLVE is permitted

KAPIA enforces physical irreversibility.
IAM.MAI enforces legitimacy irreversibility.

They must never be conflated.

⸻

9. RELATIONSHIP TO PEP / UPAD / ISPAD

UPAD
• approaches KAPIA
• handles value before crossing
• must never cross or reverse KAPIA

ISPAD
• operates only after KAPIA
• handles consequence, reporting, settlement

PEP
• defines value semantics consumed at KAPIA
• forbids value logic after crossing

⸻

10. RELATIONSHIP TO SPIRAL

KAPIA itself does not write to SPIRAL.

SPIRAL records:
• PoP turns
• EVENT closure turns

KAPIA is a precondition, not a memory.

⸻

11. FAILURE MODES

• Soft or advisory threshold → INVALID
• Late KAPIA (post-closure) → INVALID
• PoP without KAPIA → INVALID
• Refund after KAPIA → INVALID

⸻

12. CANONICAL ONE-LINE DEFINITION

KAPIA is the irreversible boundary inside an EVENT where potential collapses into admissible reality.

⸻

FINAL LOCK

• KAPIA is singular.
• KAPIA is irreversible.
• KAPIA consumes value, not truth.
• KAPIA enables PoP but does not create it.
